# i18n: cómo inyectar los textos

La librería **no compila i18n**. No tiene Paraglide, ni catálogos, ni runtime de idiomas: cada
componente con texto visible trae sus textos por defecto **en inglés** y acepta una prop
`strings` para sobreescribirlos. El idioma lo resuelve la app, en render.

El por qué (tres runtimes de Paraglide con estados independientes, el locale congelado en scope
de módulo, el copy de producto imposible de sobreescribir) está en
[ADR 0003](adr/0003-i18n-por-inyeccion.md).

## El patrón

```svelte
<script lang="ts">
	import { Modal } from '@callepuzzle/svelte-ui';
</script>

<Modal title="Editar" strings={{ close: 'Cerrar' }}>
	<!-- … -->
</Modal>
```

- La prop es `strings?: Partial<XStrings>`: sobreescribes **solo las claves que quieras** y el
  resto se queda en inglés. No hay que rellenar el diccionario entero.
- Dentro, el componente hace `const t = $derived({ ...defaultXStrings, ...strings })`. Es
  reactivo: si cambias de idioma en caliente y `strings` cambia, el texto se repinta.
- Los tipos `XStrings` y los valores `defaultXStrings` se exportan desde el barrel, así que
  puedes partir de los defaults y sobreescribir una clave, o usar el tipo como checklist:

```ts
import { defaultNavBarEndStrings, type NavBarEndStrings } from '@callepuzzle/svelte-ui';

// El tipo completo obliga a decidir cada clave; el `tsc` avisa si la librería añade una nueva.
const navBarEndStrings: NavBarEndStrings = {
	...defaultNavBarEndStrings,
	signOut: 'Cerrar sesión'
};
```

## Defaults por app: el contexto de `strings`

Repetir la prop en cada punto de uso se hace pesado en cuanto la app tiene varios componentes.
`setUiStrings` fija los textos de **todos** los componentes de una vez, con contexto de Svelte:

```svelte
<!-- src/routes/+layout.svelte -->
<script lang="ts">
	import { setUiStrings } from '@callepuzzle/svelte-ui';
	import { m } from '$lib/paraglide/messages.js';

	setUiStrings({
		formFields: { required: m.form_required(), optional: m.form_optional() },
		modal: { close: m.common_close() },
		header: { back: m.common_back(), openSidebar: m.common_menu() }
	});
</script>
```

Cada componente resuelve sus textos con la precedencia **prop `strings` > contexto > default en
inglés**: la prop sigue existiendo para puntuales, y las claves de cada slice son las mismas que
las de la prop `strings` del componente (el tipo `UiStringsMap` es el mapa de todos).

- Llámalo en el script de un componente (es `setContext`: solo vale durante la inicialización),
  típicamente el layout raíz.
- **En render**, como todo lo demás: los `m.*` de arriba se resuelven con el locale activo del
  render. Nunca construyas el objeto en scope de módulo (regla dura de abajo).
- El objeto se lee al inicializar cada componente: para cambiarlo (cambio de idioma incluido),
  re-instancia el árbol o recarga. No esperes reactividad mutándolo en caliente.
- Los tests y las stories no fijan contexto: los componentes caen en los defaults en inglés, que
  es justo lo que les permite asertar sobre textos conocidos.

## Regla dura: nunca resuelvas un mensaje en scope de módulo

En SSR un módulo se evalúa **una vez por proceso**, no por request. Un mensaje resuelto arriba de
un fichero congela el idioma para todos los usuarios que atienda ese servidor: el primer locale
que se resuelva gana para siempre. Es el bug que tenía la librería vieja en su `routes.ts`.

```ts
// ✗ MAL: `label` se resuelve al importar el módulo
export const routes: RouteMap<RouteId> = {
	'/': { label: m.routes_home(), showInMenu: true }
};

// ✓ BIEN: se resuelve en cada render
export function getRoutes(): RouteMap<RouteId> {
	return { '/': { label: m.routes_home(), showInMenu: true } };
}
```

Y en el componente que la consume, `$derived` para que reaccione al cambio de idioma:

```svelte
const routes = $derived(getRoutes());
```

Lo mismo vale para los diccionarios de `strings` (declara una función o un `$derived`, no un
`const` de módulo) y para los **schemas**: `createLoginSchema(strings)` es una factoría
precisamente para que no haya un `loginSchema` con mensajes ya compilados en scope de módulo.

## Ejemplo completo con Paraglide

Es lo que usan el demo y los dos consumidores. Paraglide se configura **en la app**, con su
plugin de Vite; la librería no sabe que existe.

```ts
// vite.config.ts
import { paraglideVitePlugin } from '@inlang/paraglide-js';
import tailwindcss from '@tailwindcss/vite';
import { sveltekit } from '@sveltejs/kit/vite';
import { defineConfig } from 'vite';

export default defineConfig({
	plugins: [
		tailwindcss(),
		sveltekit(),
		paraglideVitePlugin({
			project: './project.inlang',
			outdir: './src/lib/paraglide',
			strategy: ['cookie', 'baseLocale']
		})
	]
});
```

Un módulo con los diccionarios de la librería, resueltos **al llamar a la función**:

```ts
// src/lib/ui-strings.ts
import {
	commonStrings,
	type HeaderStrings,
	type ModalStrings,
	type NavBarEndStrings
} from '@callepuzzle/svelte-ui';
import { m } from '$lib/paraglide/messages';

/** Los textos compartidos, traducidos una vez. Función, no `const`: ver la regla dura. */
export function getCommonStrings() {
	return {
		...commonStrings,
		close: m.common_close(),
		back: m.common_back(),
		menu: m.common_menu(),
		signIn: m.common_sign_in(),
		signOut: m.common_sign_out(),
		profile: m.common_profile(),
		openSidebar: m.common_open_sidebar(),
		closeSidebar: m.common_close_sidebar(),
		avatarAlt: (name: string) => m.common_avatar_alt({ name })
	};
}

export function getHeaderStrings(): HeaderStrings {
	const c = getCommonStrings();
	return { back: c.back, openSidebar: c.openSidebar, navLabel: c.menu };
}

export function getNavBarEndStrings(): NavBarEndStrings {
	const c = getCommonStrings();
	return {
		search: c.search,
		notifications: c.notifications,
		language: c.language,
		userMenu: m.nav_user_menu(),
		profile: c.profile,
		signOut: c.signOut,
		avatarAlt: c.avatarAlt
	};
}

export function getModalStrings(): ModalStrings {
	return { close: getCommonStrings().close };
}
```

Fíjate en `avatarAlt`: las claves que necesitan interpolación son **funciones**
(`(name: string) => string`), no plantillas. Así el orden de las palabras lo decide el idioma de
destino y no la librería.

Y en el layout:

```svelte
<script lang="ts">
	import '../app.css';
	import type { Snippet } from 'svelte';
	import { Header, NavBarEnd } from '@callepuzzle/svelte-ui';
	import { locales, setLocale } from '$lib/paraglide/runtime';
	import { getHeaderStrings, getNavBarEndStrings } from '$lib/ui-strings';
	import { getRoutes } from '$lib/routes';
	import { authClient } from '$lib/auth-client';
	import type { LayoutData } from './$types';

	let { children, data }: { children: Snippet; data: LayoutData } = $props();

	// Todo `$derived`: al cambiar de locale, `m.*()` devuelve otra cosa y esto se recalcula.
	const routes = $derived(getRoutes());
	const headerStrings = $derived(getHeaderStrings());
	const navBarEndStrings = $derived(getNavBarEndStrings());
</script>

<Header {routes} homeHref="/" strings={headerStrings}>
	{#snippet title()}Mi app{/snippet}
	{#snippet navEnd()}
		<NavBarEnd
			user={data.user}
			{authClient}
			{locales}
			{setLocale}
			profileHref="/profile"
			strings={navBarEndStrings}
		/>
	{/snippet}
</Header>

{@render children()}
```

`locales` y `setLocale` son los del runtime de **tu** app: `NavBarEnd` los usa tal cual y se
tipan como `readonly string[]` y `(locale: string) => void`. No hay ningún tipo `Locale` en la
librería, precisamente para que tu unión de locales encaje sin castings.

`NavBarEnd` solo pinta el selector de idioma si `locales.length > 1` **y** `setLocale` está
definido.

### El handle y el truco de los enlaces localizados

Paraglide necesita su middleware en `hooks.server.ts`, después del de auth:

```ts
// src/hooks.server.ts
import { building } from '$app/environment';
import { sequence } from '@sveltejs/kit/hooks';
import { betterAuthHandle } from '@callepuzzle/auth/hooks';
import { paraglideHandle } from '$lib/paraglide-handle';
import { auth } from '$lib/server/auth';

export const handle = sequence(betterAuthHandle(auth, building), paraglideHandle);
```

Con la estrategia `url` (rutas localizadas del tipo `/es/...`), Paraglide necesita **ver** en el
marcado un `href` por cada locale para generar sus rutas; si todos tus enlaces son dinámicos, no
los detecta. De ahí el bloque oculto que aparece en el demo y en los consumidores:

```svelte
<!-- Paraglide descubre las rutas localizadas escaneando `href`. Este bloque existe solo
     para que las vea; no se muestra. Innecesario con la estrategia `cookie`. -->
<div hidden>
	{#each locales as locale (locale)}
		<a href={localizeHref(page.url.pathname, { locale })}>{locale}</a>
	{/each}
</div>
```

Usa `hidden` y no `style="display:none"`, y **explica por qué está ahí** en un comentario: sin
él es una línea inexplicable que se copia de repo en repo.

## Los schemas también

`@callepuzzle/core/schema` no exporta un schema de login ya construido, sino una factoría:

```ts
import { createLoginSchema } from '@callepuzzle/core/schema';
import { m } from '$lib/paraglide/messages';

// En el `<script>` del componente, no en scope de módulo.
const schema = $derived(
	createLoginSchema({
		emailError: m.login_email_error(),
		emailPlaceholder: m.login_email_placeholder(),
		emailDescription: m.login_email_description()
	})
);
```

`placeholder` y `description` van por `.meta({ … })` de zod y de ahí los recoge
`zodToFieldsJsonSchema`, así que un formulario generado desde el schema sale traducido sin tocar
los componentes de campo. Para tus propios schemas, el mismo patrón:

```ts
export function createGangSchema() {
	return z.object({
		name: z
			.string()
			.min(3, m.gang_name_too_short())
			.meta({ placeholder: m.gang_name_placeholder(), description: m.gang_name_help() })
	});
}
```

Una limitación que conviene conocer: la prop `schema` de `FormLoginMagicLink` y `FormLoginOtp`
se lee **una vez por instancia** — `superForm` no soporta cambiar el schema de un formulario ya
creado —. Si la pasas traducida en un `$derived` (como hace el demo) y el usuario cambia de
idioma con el formulario abierto, los mensajes de validación no se re-traducen hasta que el
componente se re-monta (cerrar y reabrir el modal vale). Los textos de la UI — botones, avisos,
pasos — sí reaccionan al cambio de idioma, porque esos viajan por `strings`.

## Catálogo de diccionarios

Todos los tipos y los `default*` se exportan desde `@callepuzzle/svelte-ui` (los de
`FormLoginOtp`, desde `@callepuzzle/svelte-ui/otp`).

| Componente           | Tipo                                              | Claves                                                                                                                                                                   |
| -------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| —                    | `CommonStrings` (`commonStrings`)                 | `close`, `back`, `menu`, `openSidebar`, `closeSidebar`, `required`, `optional`, `signIn`, `signOut`, `search`, `notifications`, `language`, `profile`, `avatarAlt(name)` |
| `Header`             | `HeaderStrings`                                   | `back`, `openSidebar`, `navLabel`                                                                                                                                        |
| `Drawer`             | `DrawerStrings`                                   | `closeSidebar`                                                                                                                                                           |
| `Dock`               | `DockStrings`                                     | `navLabel`                                                                                                                                                               |
| `NavBarEnd`          | `NavBarEndStrings`                                | `search`, `notifications`, `language`, `userMenu`, `profile`, `signOut`, `avatarAlt(name)`                                                                               |
| `Modal`              | `ModalStrings`                                    | `close`                                                                                                                                                                  |
| `ButtonSignOut`      | `ButtonSignOutStrings`                            | `signOut`                                                                                                                                                                |
| `UserNotLogged`      | `UserNotLoggedStrings`                            | `text`                                                                                                                                                                   |
| `FormFields`         | `FormFieldsStrings`                               | `required`, `optional`                                                                                                                                                   |
| `FormString`         | `FormStringStrings`                               | `required`, `optional`                                                                                                                                                   |
| `FormNumber`         | `FormNumberStrings`                               | `required`, `optional`                                                                                                                                                   |
| `FormTextarea`       | `FormTextareaStrings`                             | `required`, `optional`                                                                                                                                                   |
| `FormSelect`         | `FormSelectStrings`                               | `required`, `optional`                                                                                                                                                   |
| `FormCheckbox`       | `FormCheckboxStrings`                             | `required`, `optional`                                                                                                                                                   |
| `FormLoginMagicLink` | `FormLoginMagicLinkStrings`                       | `required`, `optional`, `signIn`, `magicLinkSent`, `rateLimited`, `error`                                                                                                |
| `FormLoginOtp`       | `FormLoginOtpStrings`                             | `required`, `optional`, `signIn`, `stepEmail`, `stepOtp`, `otpLabel`, `otpDescription(digits)`, `success`, `rateLimited`, `invalidCode`, `error`, `startOver`            |
| `createLoginSchema`  | `LoginSchemaStrings` (`@callepuzzle/core/schema`) | `emailError`, `emailPlaceholder`, `emailDescription`                                                                                                                     |

`Link`, `NavBarList`, `DockLink` y `Footer` no tienen textos propios: el suyo sale de las
`label`/`short` del `RouteMap` o del contenido que les pases.

Nota sobre `Dock`: su `navLabel` por defecto es `'Bottom navigation'` y **no** reutiliza
`commonStrings.menu` a propósito. Si `Header` y `Dock` conviven en la misma página, dos
landmarks `navigation` con el mismo nombre accesible incumplen la regla `landmark-unique` de
axe. Al traducirlos, dales nombres distintos.
